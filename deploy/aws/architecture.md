# SupportIQ — Production AWS Enterprise Architecture

This document describes the enterprise cloud deployment architecture for SupportIQ on Amazon Web Services (AWS), designed for 99.95% uptime, SOC2-compliance, and sub-100ms multi-tenant vector query performance.

## 2. Infrastructure Components

### A. Network & VPC Security
* **VPC**: 3 Availability Zones (AZs) with dual Public and Private Isolated subnets.
* **Public Subnets**: AWS Application Load Balancer, NAT Gateways for outbound LLM API access (OpenAI / Anthropic / Google Gemini).
* **Private Subnets**:
  * ECS Fargate Tasks (no public IPs assigned).
  * Aurora Serverless v2 PostgreSQL instances.
  * ElastiCache Redis cluster with in-transit and at-rest encryption.
* **Security Groups**:
  * `ALB-SG`: Ingress 443 from CloudFront / WAF only.
  * `ECS-SG`: Ingress 8000 only from `ALB-SG`.
  * `DB-SG`: Ingress 5432 only from `ECS-SG`.
  * `Redis-SG`: Ingress 6379 only from `ECS-SG`.

### B. Compute Layer (AWS ECS Fargate)
* **API Service**:
  * Auto-scaling based on CPU (>70%) and concurrent ALB requests (>50 req/sec per task).
  * Minimum 2 tasks across distinct AZs for zero-downtime rolling deployments (`minimumHealthyPercent: 100`).
  * Server-Sent Events (SSE) streaming enabled with proxy buffer disabling.
* **Background Worker Service**:
  * Asynchronous processing for large PDF/DOCX chunking and embedding.
  * Auto-scaling based on Redis queue depth (`QueueLength > 20`).

### C. Database & Vector Search (Amazon Aurora PostgreSQL Serverless v2)
* Engine: PostgreSQL 16 compatible with `pgvector` extension enabled.
* Scaling: Auto-scales from 0.5 ACU up to 16 ACUs based on load.
* Backup: Automated daily snapshots with 30-day point-in-time recovery (PITR).
* Multi-Tenancy: Strict `organization_id` indexing on every table (`CREATE INDEX ix_orders_org_id ON orders(organization_id)`).

### D. Caching & Message Broker (Amazon ElastiCache Redis 7)
* Multi-AZ replication group with automatic failover.
* In-memory cache for sliding-window rate limit counters and Celery queue distribution.

### E. Storage (Amazon S3)
* SSE-KMS encryption using customer-managed KMS key (CMK).
* Block all public access enabled. Documents accessed solely via pre-signed S3 URLs generated by FastAPI backend.

## 3. Production Deployment Runbook

### Step 1: Initialize Database & Vector Extensions
```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
```

### Step 2: Apply Database Migrations
```bash
alembic upgrade head
python -m backend.app.db.seed
```

### Step 3: Run ECS Task Definition
```bash
aws ecs update-service \
  --cluster supportiq-production \
  --service supportiq-api \
  --force-new-deployment
```
